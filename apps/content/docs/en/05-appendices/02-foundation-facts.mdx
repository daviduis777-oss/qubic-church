# Verified Facts

<Callout type="info" title="Re-check, September 2026">
This page used to be a "foundation facts" reference that also contained the Bitcoin bridge, a 550 BTC time lock and other claims that the re-check did not confirm. It now lists only statements that were recomputed from public data and checked independently. See [September 2026 re-check](/docs/03-results/35-corrections-september-2026).
</Callout>

A fact listed here is true as stated. Being true does not make it meaningful: several of these are exact arithmetic that earlier versions of the site over-interpreted. The right-hand column says what each fact does not show.

## The Anna Matrix (as published)

| Fact | What it does not show |
|---|---|
| The published file is a 128 x 128 table of signed bytes, compiled by hand from replies of the @anna_aigarth bot to `x+y=?`; the reply to x and y is in row `63 - y`, column `x + 64`. All 1,218 numeric bot replies in our records (948 distinct queries) match this lookup | It is not a weight file, not source code and not a memory dump. The replies and the table come from the same collection, so the match is consistency, not independent proof |
| 16,316 of 16,384 cells satisfy `M[i][j] + M[127-i][127-j] = -1` | The 68 exceptions are not a hidden layer; most are entry errors ([chapter 36](/docs/03-results/36-where-the-anna-matrix-comes-from)) |
| The matrix has full rank 128 | No meaning beyond linear algebra |
| The 26 largest Walsh coefficients reproduce about 81% of the signs; a 32-row kernel reproduces 94.5% | The table is mostly a shallow, almost linear function of the input bits |
| For 768 tested ternary input vectors, iterating `sign(M v)` ends in two period-4 cycles that are negatives of each other | Not proven for all inputs. The seven positions where these cycles are not antipodal depend on the column 30 entry error |
| Three diagonal cells have absolute values 75, 101 and 121, which are the ASCII codes of "K", "e", "y" | Under a fair chance model this is not unusual |
| The trace of the table as typed is 137 | It comes from one cell pair that is very likely an entry error; the corrected table has trace -64 |

## Bitcoin

| Fact | What it does not show |
|---|---|
| The Genesis block is 285 bytes; its nonce is 2083236893 | Nothing about Qubic |
| The Genesis output public key is a valid secp256k1 point | It is not an executable script and hides no second program |
| Block 264 (13 January 2009, 00:19:40 UTC) pays to the public key whose address is `1CFBdvaiZgZPTZERqnezAtDQJuGHKoHSzg` | Among 21,953 early keys, 17 addresses start with `1CF`, while chance predicts 16.5. See [chapter 17](/docs/03-results/17-cfb-satoshi-analysis) |
| The public key of block 4 gives an address starting with `15ubic` | A prefix like that is expected somewhere among thousands of early addresses |
| 625,284 = 283 x 47² + 137, and 625,284 mod 16,384 points to row 21, column 4 | Exact arithmetic with numbers chosen after the fact |

# Reverse-Engineering Anna.exe

<Callout type="warning" title="Correction, September 2026">
Earlier Python ports of Anna.exe were not faithful to the binary (signed bits, halting, mutation, addressing), and the constructive adder works only in a modified base-3 model. Static analysis shows versions 5 to 8 still train signed addition. See [Corrections, September 2026](/docs/03-results/35-corrections-september-2026).
</Callout>

<Callout type="info" title="One-line summary">
`Anna.exe` is CFB's Aigarth evolution engine, it evolves a 100-cell ternary lookup-table cellular automaton to perform 7-bit addition. We disassembled it and rebuilt a simplified model of the algorithm. In that modified model, composition (evolve a 1-bit adder, then wire seven copies) reaches a perfect score where blind monolithic evolution stalls. Whether the unmodified substrate can reach 0 is not shown.
</Callout>

## 1. What the binary is

`Anna.exe` is CFB's (Come-from-Beyond's) binary, verified against his own Discord notes and screenshots. It is a self-contained **Aigarth evolution engine**, **not** the published 128×128 Anna Matrix and **not** part of `qubic/core`. It is a PE32+ x86-64 executable (MSVC linker 14.51, built 10 June 2026), imports **`KERNEL32.dll` only** (static CRT), and does no file or network I/O. Everything operational is generated at runtime in a ~5.84 MB BSS arena; there is no embedded Anna data file.

It came with a bounty: 1,000,000,000 QU to the first person whose run reaches "score 0" within ~23 hours (which CFB flagged playfully himself). A reachability analysis (companion in the working folder) finds it effectively unreachable by the binary's blind single-trit search: the error floor rises sharply with problem size, and CFB's own screenshot shows ~41% error on the full 7-bit task.

## 2. What it computes

It trains a substrate to perform **7-bit + 7-bit binary addition**. The disassembly is unambiguous: `lea eax, [rdx + r8]` computes row + col = the sum, and the individual bits are extracted with `vpand` against the masks (1, 2, 4, …, 128) and stored as the target. Two nested loops run −64..63 (128 each) = **16,384 operand pairs**, which equals the element count of Anna's 128×128 matrix. Fourteen input cells carry the two 7-bit operands; eight output cells must equal the eight bits of (a + b).

The only program-specific format string (recovered in `strings_ascii.txt`):

```
EPOCH %d (%d) :: %lld :: pos = %d | neg = %d | neu = %d
```

where `(%d)` is the average ticks-to-halt, `%lld` is the error being driven to 0, and pos / neg / neu count accepted-improving / reverted-worsening / neutral mutations.

## 3. The core loop

A **(1+1) evolution strategy** (a hill-climber with neutral drift):

1. Build the 16,384-task dataset; split into two pools by an `RDRAND` coin-flip; score one pool (~8,192 tasks).
2. Randomly seed (via `RDRAND`) a ternary substrate of per-cell lookup tables (~5.9M trits, values in `{0, 1, 2}`).
3. Each epoch: mutate exactly one trit, re-score, **accept if not worse, revert (memcpy backup) if worse**, neutral moves are accepted.
4. Score = total wrong output bits, minimized toward 0.
5. Telemetry every 100 epochs, for 1,000,000 epochs.

Confirmed addresses and constants (from `main_loop.asm` / `fitness.asm` / `v2_main.asm`): main loop at VA `0x140001a90`; fitness function at VA `0x140001060` (returns a 64-bit score; the `memset(work, 0, 0x190)` zeroes 100 int32 cells; `vpcmpeqd` + `vpandn` builds the not-equal mismatch mask). Epochs `0xf4240` = 1,000,000; print cadence 100; 100 cells; 100 timesteps; 14 inputs; 8 outputs; per-cell LUT 1846 qwords (14,768 B = 59,072 entries, ≈ `3^10` = 59,049 for a 10-trit window); substrate 1,477,824 bytes; mod-3 magic `0xaaaaaaaaaaaaaaab`; RNG = `RDRAND`. (Earlier versions described the mutation as exactly ±1 mod 3; v1 actually uses an unsigned underflow that differs from a mathematical mod 3.)

## 4. The structure it embodies

A 100-cell ternary **lookup-table cellular automaton**. Each cell updates from a packed window of ~8–10 neighbour cells via its own lookup table, runs for up to 100 timesteps with a halting condition (keep stepping while any of 8 control cells equals 2). This is the concrete realization of "an Aigarth neuron is a lookup table."

Two honest notes from the disassembly:

- **No published matrix inside.** `Anna.exe` does not contain the 128×128 signed-int8 Anna Matrix. The only link to "128×128" is that 16,384 = the task count = the matrix's element count. The binary is a newer evolution demo of the generative principle, not the published artifact.
- **An aliasing quirk.** Each per-cell table holds 59,072 entries (≈ `3^10` = 59,049, a 10-trit window). The shipped binary packs the window base-4 (`shl 2`), so a window value can index past a cell's block and alias into the neighbouring cell's table, coupling cells and making the search slightly harder than an idealized base-3 model.

## 5. Reimplementation and what it shows

**`anna_zero_proof.c`, an adder in a modified model.** It does not search; it hand-constructs a ternary lookup-table CA as a synchronous ripple-carry adder (sum = XOR of three, carry = majority of three) and verifies 0 wrong bits over all 16,384 pairs. Earlier versions said this proves the unmodified substrate capable with under a third of the cells. That did not hold up: the construction uses 37 cells, base 3 instead of the binary's base 4, unsigned instead of signed addition, and separate control cells held at 2 instead of the output cells as halting cells. With the binary's rule, where the output cells are the halting cells, the same construction stops after one tick and gets 13,468 of 16,384 sums wrong. It is a correct unsigned 7-bit adder in its own modified model, not a zero-error solution in the unmodified `Anna.exe` substrate.

**`anna_evolve_compose.c` / `anna_live.c`, composition reaches 0 in the modified model.** Using the same (1+1) greedy on the modified lookup-table CA, evolve a one-bit full adder (8-row truth table) to error 0 in a few hundred evaluations, then compose seven ripple-carry copies into a **perfect 7-bit adder: 0 of 131,072 wrong bits over all 16,384 pairs** (it further composes to a 10-bit adder, exact over 1M pairs). `anna_live.c` reproduces the `EPOCH …` telemetry format while doing it. This follows CFB's own 2019 Scratch vision (evolve A+B, drag-and-drop to compose), in our model rather than in the binary.

**Faithfulness and coverage.** Earlier versions called the Python port (`aigarth_engine.py`) a faithful port of the binary apart from the random source. That is withdrawn. Besides the RNG, it uses 64 random targets instead of the 16,384 signed addition pairs and scoring pool, draws input, output and halting cells independently, wraps whole-table addresses modulo the table size, and mutates with a mathematical mod 3 instead of v1's unsigned underflow. Results from the port describe the port, not the binary. At the port's 64-task scale, the raw engine learns (74–87% train fitness) but memorizes: on unseen inputs it generalizes at chance, and only ~2–3% of the 5.9M-trit substrate is ever read. Whether the binary reaches error 0 on its real 16,384 targets is open; the reachability analysis suggests the monolithic search stalls at a high error floor, but that is a hypothesis.

The v2→v3 walk (auto to manual unstick in about 90 minutes) empirically confirmed the diagnosis that the auto direction-flip is unreliable. Separately, every escape strategy we tested (annealing, direction-invert, eager iterated local search) underperformed plain greedy; the load-bearing piece is the preserved global best, not the flip, and the missing ingredient is recombination, a memetic island search with crossover solved the 2-bit case exactly.

## 7. Determinism (the verification-relevant point)

`Anna.exe` uses `RDRAND` for both task generation and every mutation, no seed, no PRNG state. Therefore every run is unique and non-reproducible, and the binary cannot regenerate any specific published matrix. On this analysis the bounty is effectively unreachable by blind monolithic search (the error floor rises sharply with problem size), and we make no claim to have reached score 0 in the sealed binary. Our reimplementations are the deliberate opposite: a seeded `splitmix64` PRNG, fully deterministic and reproducible, with exhaustive verification over the full input space. That deterministic, independently re-computable property is exactly what makes evolved artifacts verifiable on-chain: anyone can re-run the integer kernel and get bit-identical results.

## 8. The single most important finding

Monolithic (1+1) evolution stays far above 0 (CFB's own screenshot shows ~41% wrong partway through, and the floor rises sharply with size), yet evolving a tiny one-bit full adder (0 error in a few hundred evaluations) and composing seven ripple-carry copies yields a perfect 7-bit adder in our modified model, 0 of 131,072 wrong bits over all 16,384 pairs. In that model, composition reaches 0 where monolithic evolution does not. The corollary is the un-hyped one: "score 0" is a learned arithmetic circuit, not intelligence; and at the 64-task scale we tested, the raw engine memorizes rather than generalizes.
